Model Search and Automatic Model Development

Overview

Model development is a sequence of decisions: one compartment or two, an absorption lag or not, which parameters carry between-subject variability, whether the residual error needs a time-varying term, which covariates earn their place.

Each of those decisions is a small, mechanical search over a space of candidate models, ranked by a criterion and filtered by whether the fit can be trusted at all. ferx can run them for you — the same tool chain as Pharmpy’s amd, driven from R:

Function Decides Ranks on
ferx_modelsearch() structural model: absorption, peripherals, transits, lag time BIC (mixed)
ferx_iivsearch() which parameters carry an eta, and which etas are correlated BIC (IIV)
ferx_iovsearch() which parameters carry inter-occasion variability BIC (random)
ferx_ruvsearch() the residual-error model likelihood-ratio test
ferx_covsearch() which covariate effects to include (SCM) likelihood-ratio test
ferx_allometry() allometric scaling on body size — a transform, not a search —
ferx_amd() all of the above in order, each step starting from what the last selected per step 
library(ferx)
run_dir <- file.path(tempdir(), "search")
Note

A search is only as good as the fits underneath it. Read Overview first: everything here assumes a base model that fits, and strictness settings you have thought about.

The search space is MFL

A space is written in Pharmpy’s Model Feature Language and quoted verbatim. ferx never translates R arguments into MFL — the space you write is the space the engine reads, which is also what makes it portable to and from Pharmpy.

ABSORPTION(FO); PERIPHERALS(0..1); LAGTIME([OFF,ON])
IIV?(@PK, exp); COVARIANCE?(IIV, *)
  • A statement without ? is structural: every candidate has it.
  • A statement with ? is exploratory: the search decides.
  • @PK, @IIV, @CONTINUOUS and @CATEGORICAL resolve against your model and your dataset, so one space travels across models.

ferx_search_space() expands those symbols so you can see what a one-line space actually means on your model, before committing to a run:

ex_cov <- ferx_example("two_cpt_oral_cov")
ferx_search_space("COVARIATE?(@IIV, @CONTINUOUS, [pow, lin])",
                  model = ex_cov$model,
                  data  = ex_cov$data)

The configuration file

A search can be driven two ways: a .ferxsearch file, or inline arguments. The file is the reproducible artifact — it carries the space, the criterion, the strictness gate, the run settings and the per-tool sections in one place, and its paths are relative to itself, so it travels with the model.

The loader is strict, and it is strict here rather than three fits into a run: an unknown section, an unparseable space, an empty space, an unrecognised [rank] type, an invalid [rank.penalties] charge and a coverage gap are all errors at load, each naming the offender.

TipBoth entry forms are the same search

Every tool accepts either config = or inline arguments, never a mix. The inline form builds the same configuration in the engine and goes through the same loader, so a one-off run and a filed one cannot drift apart.

ferx_iovsearch() is the same idea over occasions, and it reads its occasions from the base model’s iov_column: a model that declares none has nothing to search, and the tool says so rather than searching an empty space.

Each candidate is a residual-error feature — a power term, a combined error, a time-varying error — tested against the parent by likelihood-ratio test at p_value. The per-iteration table carries the p-value it decided on, so “which residual form won, and at what p” is a table rather than prose.

Covariates and allometry

ferx_covsearch() is stepwise covariate modelling: scm-forward or scm-forward-then-backward, with p_forward and p_backward thresholds and adaptive scope reduction.

ferx_covsearch(
  model        = ex_cov$model,
  data         = ex_cov$data,
  search_space = "COVARIATE?(@IIV, @CONTINUOUS, [pow, lin])",
  p_forward    = 0.01,
  p_backward   = 0.001,
  directory    = file.path(run_dir, "covsearch")
)

ferx_allometry() is not a search at all — it is the convention (fix = 0.75 on clearances, fix = 1 on volumes, centred on a reference weight) applied as a model transform. With fit = FALSE it returns the edited model without fitting anything, so allometry can be a step in a hand-built workflow:

al <- ferx_allometry(ex_cov$model, ex_cov$data,
                     covariate = "WT", reference = 70, fit = FALSE)

The whole pipeline: ferx_amd()

ferx_amd() runs the tools in order, each step starting from the model the previous step selected. One space describes the whole pipeline: the engine partitions it by statement kind and hands each step only the statements its own tool can read.

Warningcriterion says what value is on

It is not always the step’s own scale. With cwres_prescreen = TRUE, ruvsearch screens its candidates against the parent’s CWRES and refits only the winner to the data: those rows are marked screened and carry criterion = "cwres_ofv", and their numbers must not be compared with a data OFV. The engine default is cwres_prescreen = FALSE — every candidate is fitted to the data, and the rows read criterion = "ofv" like any other step, which is what the runs in this chapter do. The column is there so you do not have to remember which of the two you are reading.

Reading a run back

Every tool writes its run to directory, and the tables there are the ones the R object carries — no recomputation in R, so the two cannot disagree. An interrupted run, or one driven from the ferx command-line tool, reads back the same way:

ferx_search_results(file.path(run_dir, "modelsearch"), type = "models")[,
  c("id", "parent", "layer", "criterion", "rank", "converged", "passed")]
    id parent layer criterion rank converged passed
1 base   <NA>     0 -261.8480    1      TRUE   TRUE
2 run1   base     1 -259.5900    2      TRUE   TRUE
3 run2   base     1 -252.4470   NA      TRUE  FALSE
4 run3   run1     2 -250.1891   NA      TRUE  FALSE
5 run4   run2     2 -250.1891   NA      TRUE  FALSE
  • type = "candidates" (the default) reads candidates.csv
  • type = "models" reads a structural or variability search’s models.csv
  • type = "steps" reads a stepwise search’s steps.csv

Columns come from the engine’s own column list and are typed on the way in: logicals are logical, an empty cell is NA rather than NaN. A partial table, written when a run is cancelled, reads back too.

resume = TRUE picks a run up where it stopped using the journal in directory; threads and retries mirror ferx_bootstrap(), which is the closest existing tool.

Notes and limitations

  • Some .ferxsearch sections have no R tool. The engine accepts a section for every tool it knows, which is more than this package binds — [globalsearch] and [structsearch] today. Such a file loads, and ferx warns that no R tool consumes the section, because the stepwise tools would otherwise run a stepwise search without saying so. The warning names where the section can be run instead when there is somewhere: [globalsearch] is the engine’s own tool, behind ferx globalsearch. [structsearch] is accepted vocabulary with no engine module behind it yet, so it is reported without a remediation rather than with one that names a command that does not exist.
  • The strictness gate is shared. [strictness] applies to every tool, and converged / passed are columns of every table that reports on fitted candidates — the candidate tables, the structural and variability models.csv, the covsearch and ruvsearch steps.csv, and AMD’s own step table. They are not on the per-stage ranking summaries an R object carries alongside those (ferx_iivsearch()$steps is step, kind, parent, id, criterion, d_criterion, rank, best), which rank models the candidate rows already reported on. Inside an AMD step the init-stall gate is turned off by design: each step starts from a model already at its own optimum, where “did not move from the initial estimates” is the expected outcome rather than a failed fit.
  • Search is not a substitute for judgement. These tools decide within the space you give them, on the criterion you choose, among the fits the gate lets through. All three are yours.
