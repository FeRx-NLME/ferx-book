Model development and selection

DATA → MODEL → ESTIMATE ⇄ EVALUATE → SIMULATE → REPORT

Where you are

The base model is fitted (Initial estimates and a first fit) and evaluated (Diagnosing the model, Simulation-based evaluation: VPC). The diagnostics hinted at covariate relationships (ETA_CL correlated with CRCL and WT) and flagged autocorrelated residuals. Model development means fitting alternatives and choosing between them. You can do that by hand: write a candidate, fit it and compare. Or let ferx’s search tools generate, fit, gate and rank candidates from a search space. This chapter shows both.

The data

base <- ferx_example("two_cpt_oral_base")
cov <- ferx_example("two_cpt_oral_cov")

Comparing fitted models

two_cpt_oral_cov is a prespecified covariate model for the same data. Body weight scales CL and V1 through a shared exponent THETA_WT, and creatinine clearance scales CL:

invisible(ferx_model_get_section(cov$model, "individual_parameters"))
#> # [individual_parameters]
#>   CL = TVCL * (WT / 70)^THETA_WT * (CRCL / 100)^THETA_CRCL * exp(ETA_CL)
#>   V1 = TVV1 * (WT / 70)^THETA_WT * exp(ETA_V1)
#>   Q  = TVQ  * exp(ETA_Q)
#>   V2 = TVV2 * exp(ETA_V2)
#>   KA = TVKA * exp(ETA_KA)
fit_base <- ferx_fit(base$model, base$data, verbose = FALSE)
fit_cov <- ferx_fit(cov$model, cov$data, verbose = FALSE)

Likelihood ratio test and information criteria

Both are FOCEI fits to the same data, and the base model is nested in the covariate model (fix both exponents at 0). The difference in OFV is therefore a likelihood ratio statistic, with degrees of freedom equal to the number of added parameters:

d_ofv <- fit_base$ofv - fit_cov$ofv
df <- fit_cov$n_parameters - fit_base$n_parameters
c(d_ofv = d_ofv, df = df, p_value = pchisq(d_ofv, df, lower.tail = FALSE))
#>         d_ofv            df       p_value 
#> 13.9235928014  2.0000000000  0.0009473931

For non-nested models, use information criteria. fit$aic and fit$bic are the classical AIC and BIC. ferx_bic() computes four BIC variants that differ in how parameters are penalised:

type Penalty added to the OFV
"mixed" (default) random-effect parameters × log(subjects) + fixed-effect parameters × log(observations)
"fixed" all parameters × log(observations); equals fit$bic
"iiv" variance parameters × log(subjects), for comparing variability structures
"random" all parameters × log(subjects)

Here the covariate model is better on every criterion.

Is the fit eligible at all?

A converged fit can still be unfit for comparison: it may never have left its initial estimates, have a parameter at a bound, or have an ill-conditioned covariance matrix. check_strictness() applies such gates and returns the reasons for failure:

check_strictness(fit_cov, require_covariance = TRUE)
#> $passed
#> [1] TRUE
#> 
#> $failures
#> character(0)
#> 
#> $skipped
#> character(0)

The fit from NCA-based starting values in Initial estimates and a first fit converged to a much worse OFV. The gates reject it:

fit_nca <- ferx_fit(base$model, base$data, inits_from_nca = TRUE, verbose = FALSE)
check_strictness(fit_nca)
#> $passed
#> [1] FALSE
#> 
#> $failures
#> [1] "condition number 1.1559e+10 exceeds 1.0000e+03"
#> 
#> $skipped
#> character(0)

The gates and their defaults: require_converged = TRUE, require_covariance = FALSE, max_condition_number = 1000, max_correlation = 0.95, reject_on_boundary = TRUE and reject_init_stall = TRUE. Set a threshold to NULL, or a flag to FALSE, to disable that gate. reject_init_stall assumes a cold start from the model file’s initial values, so turn it off when candidates start from a previous model’s estimates.

Search configurations

WarningMaturity: alpha

The ferx-core pages for the search tools carry the maturity label alpha. See feature maturity.

The search tools read a .ferxsearch configuration file (TOML) that names the base model and data and states the search. Four bundled examples carry one as $search:

Example Search file for
two_cpt_oral_base covariate search ([covsearch]), plus an [allometry] section (Covariate modeling)
two_cpt_oral_cov a configuration with a BIC ranking, used here to show loading
warfarin structural search ([modelsearch])
one_cpt_transit residual error search ([ruvsearch])

ferx_search_config() loads a file with the engine’s own strict loader, so an invalid space or a misspelt section fails before anything is fitted:

The file’s sections, as shown in the printout: base and data (paths relative to the file); [space] with the search space as mfl; [rank] with the ranking criterion; [strictness] with the gates from above; [run] with threads, retries and resume; and a section per tool. The object returned holds the same information as a list:

cfg_cov <- ferx_search_config(ferx_example("two_cpt_oral_cov")$search)
cfg_cov$rank$type

#> [1] "allometry" "covsearch"

The search space

The space is written in the Model Feature Language (MFL). COVARIATE?(@IIV, @CONTINUOUS, [pow, lin]) means: every parameter with a random effect, crossed with every continuous covariate, as a power or linear effect, each optional (?). The ? is accepted on four keywords only – COVARIATE, IIV, IOV and COVARIANCE – and marks that statement as something the search may decline; written without it, every candidate carries the feature. The other keywords, ABSORPTION and PERIPHERALS among them, enumerate the alternatives to try instead. The @ symbols resolve against the model’s [covariates] block and its random effects, so one space travels between models: @CATEGORICAL selects the categorical covariates as @CONTINUOUS selects the continuous ones. ferx_search_space() parses MFL text and, given a model and data, expands the symbols into the concrete candidates:

ferx_search_space("COVARIATE?(@IIV, @CONTINUOUS, [pow, lin])")
#> <ferx search space> (as written)
#>   mfl = COVARIATE?(@IIV, @CONTINUOUS, [pow, lin])
#> 
#>                                  feature   keyword optional
#> 1 COVARIATE?(@IIV,@CONTINUOUS,[pow,lin]) COVARIATE     TRUE
space <- ferx_search_space(cfg$mfl, model = base$model, data = base$data)
nrow(attr(space, "covariate_effects"))
#> [1] 20
head(attr(space, "covariate_effects"))
#>   parameter covariate effect op optional
#> 1        CL        WT    pow  *     TRUE
#> 2        CL        WT    lin  *     TRUE
#> 3        CL      CRCL    pow  *     TRUE
#> 4        CL      CRCL    lin  *     TRUE
#> 5        V1        WT    pow  *     TRUE
#> 6        V1        WT    lin  *     TRUE

ferx_search_coverage() reports, without fitting, whether the engine can build candidates for each feature of a space:

ferx_search_coverage(space)
#>                                  feature covered reason
#> 1 COVARIATE?(@IIV,@CONTINUOUS,[pow,lin])    TRUE   <NA>
ferx_search_coverage("ABSORPTION(SEQ-ZO-FO)")
#>                 feature covered
#> 1 ABSORPTION(SEQ-ZO-FO)   FALSE
#>                                                                                                                                                                                                                                                                                                                       reason
#> 1 sequential zero-order-then-first-order absorption is not one input term on a standard disposition but a depot of its own, filled at a constant rate and emptied by `ka`; there is no template for it and the search does not generate one. Write it by hand — `examples/sequential_absorption.ferx` — and search around it

Sequential zero- then first-order absorption is not generated by the search. Absorption and bioavailability shows the bundled model for it, which you can use as a base model instead.

An uncovered feature is not quietly dropped. Asking for one in a configuration file is an error at load, before anything is fitted, because a search that silently narrowed its space would answer a different question than the one you posed:

uncovered <- file.path(book_tempdir("search-space"), "uncovered.ferxsearch")
writeLines(sub('mfl = .*', 'mfl = "ABSORPTION([FO,SEQ-ZO-FO])"', readLines(base$search)), uncovered)
tryCatch(ferx_search_config(uncovered), error = function(e) sub(".*mfl: ", "", conditionMessage(e)))
#> [1] "the search space asks for 1 feature ferx cannot build a candidate for:\n  - ABSORPTION(SEQ-ZO-FO): sequential zero-order-then-first-order absorption is not one input term on a standard disposition but a depot of its own, filled at a constant rate and emptied by `ka`; there is no template for it and the search does not generate one. Write it by hand — `examples/sequential_absorption.ferx` — and search around it\nSee the coverage table at https://ferx-nlme.github.io/ferx-core/tools/search.html#coverage"

That is what ferx_search_coverage() is for: check a space before you file it.

Covariate search

ferx_covsearch() runs a stepwise covariate search. In each forward step it fits every remaining candidate effect and adds the one with the largest significant OFV drop at p_forward. The backward phase then removes effects whose removal is not significant at the stricter p_backward. The bundled configuration uses p_forward = 0.01 and p_backward = 0.001:

cs_dir <- book_tempdir("covsearch")
cs <- ferx_covsearch(config = base$search, directory = cs_dir, progress = FALSE)
cs
#> ferx covariate search (scm-forward-then-backward)
#>   Data:  /home/runner/work/_temp/Library/ferx/examples/search/../data/two_cpt_oral_cov.csv
#>   Wrote: /tmp/Rtmpow0tXl/covsearch
#>   OFV:   -1185 (base) -> -1185 (step 3)
#> 
#> Steps (the candidate selected at each step):
#>  step    phase parameter covariate   form  dofv  p_value converged passed
#>     1  forward        CL      CRCL linear 6.687 0.009712      TRUE   TRUE
#>     3 backward        CL      CRCL linear 6.675 0.009776      TRUE   TRUE
#> 
#> 4 candidates excluded by the strictness gate; summary() lists them.
#> 
#> Final covariate relations:
#>   (none - the base model was not improved on)

The forward phase added CL ~ CRCL (linear) at p = 0.0097, below p_forward. That p-value is above p_backward, so the backward phase removed the effect again. The search returns the base model. Candidates excluded by the strictness gate are kept in the step table with their reason:

cs$steps[!cs$steps$passed, c("step", "parameter", "covariate", "form", "failures")]
#>    step parameter covariate   form
#> 8     1        V1      CRCL linear
#> 20    1        KA      CRCL linear
#> 22    2        CL        WT linear
#> 38    2        KA      CRCL linear
#>                                                                                                                         failures
#> 8           condition number 8.1386e8 exceeds 1.0000e3; parameter correlation |r| = 1.0000 exceeds 0.9500 (TVKA ~ THETA_V1_CRCL)
#> 20     condition number 1.3933e10 exceeds 1.0000e3; parameter correlation |r| = 1.0000 exceeds 0.9500 (THETA_KA_CRCL ~ PROP_ERR)
#> 22          condition number 7.7525e8 exceeds 1.0000e3; parameter correlation |r| = 1.0000 exceeds 0.9500 (TVV1 ~ THETA_CL_CRCL)
#> 38 condition number 2.9288e9 exceeds 1.0000e3; parameter correlation |r| = 1.0000 exceeds 0.9500 (THETA_CL_CRCL ~ THETA_KA_CRCL)

print() shows the selected step of each phase. summary() on the result adds every candidate of every step; the same table is cs$steps. The run directory holds the per-step journals, steps.csv and final.ferx. ferx_search_results() reads the step table back from disk:

list.files(cs_dir)
#> [1] "backward-3" "base"       "final.ferx" "forward-1"  "forward-2" 
#> [6] "steps.csv"
steps <- ferx_search_results(cs_dir, type = "steps")
attr(steps, "tool")
#> [1] "covsearch"

The search can also be stated inline. Here it is restricted to CL, with a less strict backward level:

cs_cl <- ferx_covsearch(model = base$model, data = base$data,
                        search_space = "COVARIATE?(CL, [WT, CRCL], [pow, lin])",
                        p_forward = 0.01, p_backward = 0.01,
                        directory = book_tempdir("covsearch-cl"), progress = FALSE)
cs_cl$included
#>   parameter covariate   form         origin
#> 1        CL      CRCL linear forward step 1
c(base_ofv = cs_cl$base_ofv, final_ofv = cs_cl$final_ofv)
#>  base_ofv final_ofv 
#> -1185.423 -1192.110

The selected covariate model depends on the search space and the significance levels. A search result is evidence, not a decision. The rest of The analysis workflow continues with the prespecified two_cpt_oral_cov model, which the comparison above supports.

Structural search

ferx_modelsearch() searches structural features: absorption, elimination, peripheral and transit compartments, and lag time. It ranks the candidates on a criterion, the mixed BIC by default. The warfarin configuration searches a peripheral compartment and a lag time:

warf <- ferx_example("warfarin")

Residual error search

ferx_ruvsearch() tests four families of residual error extensions against the current error model, using the likelihood ratio test at p_value:

  • IIV_on_RUV: a random effect on the residual error magnitude. It needs an estimation method with interaction.
  • power: a proportional error raised to an estimated power.
  • combined: an additive component added to the proportional one.
  • time_varying: a residual error magnitude that differs below a time-after-dose cutoff, set at quantiles given by groups.

Up to max_iter accepted features are stacked. The bundled configuration searches the analytic transit model one_cpt_transit:

transit <- ferx_example("one_cpt_transit")
rs <- ferx_ruvsearch(config = transit$search, directory = book_tempdir("ruvsearch"), progress = FALSE)

cwres_prescreen changes what those numbers are. With it on, candidates are screened against the parent’s CWRES rather than fitted to the data, which is cheaper but puts the criterion on a different scale. Two runs that differ only in that flag, everything else held equal:

ruv <- function(prescreen) {
  ferx_ruvsearch(model = transit$model, data = transit$data, p_value = 0.05, max_iter = 1,
                 retries = 0, cwres_prescreen = prescreen,
                 directory = book_tempdir(paste0("ruvsearch-", prescreen)), progress = FALSE)
}
rs_data <- ruv(FALSE)
rs_screen <- ruv(TRUE)
screened <- startsWith(rs_screen$candidates$id, "cwres")
rbind(fitted_to_data = range(rs_data$candidates$criterion[rs_data$candidates$id != "input"]),
      screened_on_cwres = range(rs_screen$candidates$criterion[screened]))
#>                         [,1]       [,2]
#> fitted_to_data    -1070.0829 -1058.8200

The two sets of numbers are not comparable, and the screening rows are the ones whose id starts with cwres. Note that the cheaper pass also selected differently here, so treat prescreening as a different search rather than a faster one. The engine default is cwres_prescreen = FALSE, which is what the configuration run above used.

The search accepted a time-varying residual error in the first iteration, and nothing further in the second. The base model of this workflow, which carried a residual autocorrelation warning in Diagnosing the model, can be searched the same way with the inline arguments (model, data, p_value, max_iter, …).

Variability search

The space is written with IIV and COVARIANCE statements, and ? marks what the search may decide. The printed output has three steps. The eta-count stage removes etas from the input structure – top_down_exhaustive tries every subset, not one deletion at a time, so the candidates include structures with two or three etas gone. The block stage then offers covariance blocks over the etas that survived. The third step, compare_to_input, puts the winner of the block stage back against the input structure, and it is there that the selection is made. Candidates are ranked on the BIC(iiv), which is what rank = "bic" means for this tool.

Read the printed output carefully. The input model is a candidate in its own right: the step tables rank it, and in the eta-count stage it ranks first. The strictness gate is separate from that ranking. It rejected 3 of the fitted models, and one of them reached a better criterion than the winner did:

iiv$models[, c("id", "structure", "criterion", "rank", "passed")]
#>       id                 structure  criterion rank passed

The input carries no rank in the combined table above because it is the parent each stage starts from. A search result is a ranking of what passed, not proof that the winner is the best model fitted.

With algorithm = "skip" the eta-count stage is left out and only the block stage runs, which is the cheap way to ask one question: should CL and V share a covariance block? Skipping the eta-count stage means naming the block stage explicitly – asking for neither is an error rather than a search with nothing left to do. The statements name parameters, not etas:

Two structures are compared here: the input’s block_omega (ETA_CL, ETA_V) and the diagonal alternative. The input is kept – but read why. The diagonal candidate reaches the better criterion of the two, and it is out because it fails the strictness gate. The failures column gives the reason:

with(iiv_block$models, failures[!is.na(failures)])
#> [1] "stalled at the initial estimates: no free parameter moved more than 1% of its initial value (#751)"

No free parameter moved more than 1% of its initial value, so reject_init_stall refused the fit. Whether that is the right call here depends on where the candidate started, which the printed output does not say: a candidate handed its parent’s optimum can sit still because it is already converged, which is why ferx_amd() turns this gate off inside its steps (below). Read a gated-out candidate as unjudged rather than as rejected on merit, and refit it yourself if it matters. A selection is only as meaningful as the gate that produced it.

The whole pipeline at once

ferx_amd() runs the tools above in order as one automatic model-development pipeline: structural, IIV, residual, IOV, allometry, covariates. One search space describes the whole pipeline, and the engine hands each step only the statements its tool can read. A step the space says nothing about is skipped, and says so.

ferx_amd_plan() shows that plan without fitting anything, which is the cheap way to check a configuration before spending the run:

amd_ex <- ferx_example("warfarin_amd")
plan <- ferx_amd_plan(config = amd_ex$search)

Getting the result out of an AMD run takes a little care, because two fields both look final and are not the same thing. $final_model is the model text the pipeline ended on, written to $final_model_path; the fitted object is $fit. $final_ofv and $d_ofv give the end point and the change from the start, negative being an improvement:

c(final_model = class(amd$final_model), fit = class(amd$fit))

#> [1] "final.ferx"

Each step that ran also has an entry under $tools, named by its position and pipeline step. Watch the naming: the entry is keyed on the pipeline step, while its $directory is the tool that implemented it, and the two need not agree – 01-structural was run by modelsearch:

names(amd$tools)

An entry is a plain list, not the object the tool would return on its own: it carries what the step decided (status, reason, criterion, selected, seconds), its slice of the candidates, and the engine’s own table read back from the run directory. Run a tool directly when you want its fit and its own options.

Tools not available from R

ferx-core also has a global search. It runs from the ferx command line and has no R function in the pinned ferx-r build. See the ferx-core tools pages.

A .ferxsearch file may still carry a section for such a tool. The loader validates section names against a fixed vocabulary, which runs ahead of what this package binds and, in the case of [structsearch], ahead of the engine itself; a name outside that list is an error. The file loads, and ferx warns rather than running a search that quietly ignores part of its own configuration. Where the section can be run somewhere, the warning says where:

sections_dir <- book_tempdir("search-sections")
unconsumed <- function(section, body) {
  path <- file.path(sections_dir, paste0(gsub("\\[|\\]", "", section), ".ferxsearch"))
  writeLines(c(readLines(base$search), "", section, body), path)
  tryCatch(ferx_search_config(path), warning = conditionMessage)
}
unconsumed("[globalsearch]", '  algorithm = "exhaustive"')
#> [1] "ferx_search_config: [globalsearch] has no R tool in this package, so it is ignored - a search run from this file does what its other sections say. To run [globalsearch], use the `ferx globalsearch` command-line tool."
unconsumed("[structsearch]", "  x = 1")
#> [1] "ferx_search_config: [structsearch] has no R tool in this package, so it is ignored - a search run from this file does what its other sections say."

[globalsearch] has an engine tool behind it, so the message names ferx globalsearch. [structsearch] is accepted vocabulary with no engine module yet, so it is reported without a remediation that would name a command nobody can run.

Only a .ferxsearch file can carry a per-tool section ([modelsearch], [iivsearch], [covsearch], …); the inline form runs each step at its own defaults.

print() and summary() exist for the results of all of them: ferx_covsearch, ferx_modelsearch, ferx_ruvsearch, ferx_iivsearch, ferx_iovsearch and ferx_amd objects. ferx_search_config and ferx_search_space objects have print() methods.

Pitfalls

  • Keep search directories. The book writes them to a temporary directory. In a project, write them next to the analysis: they hold every candidate model, the tables and final.ferx, and they make resume possible.
  • ferx_search_results() needs the right type. The covariate and residual error searches write steps.csv, the structural search models.csv. Neither wrote a candidates.csv here, so the default type = "candidates" finds no table for these runs.
  • Compare like with like. OFV differences and likelihood ratio tests need the same data, the same estimation method and nested models.
  • Thresholds change the answer. Record the space, the significance levels and the criterion together with the selected model. The .ferxsearch file is that record.

Summary

  • Compare fitted models by likelihood ratio test (nested) or with fit$aic, fit$bic and ferx_bic(). Gate candidates with check_strictness().
  • Describe searches in .ferxsearch files; check them with ferx_search_config(), ferx_search_space() and ferx_search_coverage().
  • Run covariate, structural and residual error searches with ferx_covsearch(), ferx_modelsearch() and ferx_ruvsearch(), and read their tables with ferx_search_results().
  • Search the random-effect structure with ferx_iivsearch() and the occasion structure with ferx_iovsearch(); both can change the IIV structure, so read what they selected rather than only the criterion.
  • Run the whole order as one pipeline with ferx_amd(), after checking it with ferx_amd_plan(). A step the space says nothing about is skipped, and the step table says why.
