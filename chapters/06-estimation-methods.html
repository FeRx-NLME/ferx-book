Estimation methods and controlling the fit

DATA → MODEL → ESTIMATE ⇄ EVALUATE → SIMULATE → REPORT

Where you are

Initial estimates and a first fit fitted the base model with the method from its model file (FOCEI). ferx offers several estimation methods, and every method and optimizer can be tuned. This chapter shows how to choose a method, chain methods, follow what the optimizer does, and control the fit through settings. It ends with multi-start and background fits.

The data

library(ferx)
library(dplyr)
library(ggplot2)

The base model of the workflow thread, plus the smaller warfarin example for the method comparison:

base <- ferx_example("two_cpt_oral_base")
warf <- ferx_example("warfarin")
# Model copies written in this chapter go to a scratch directory, never into the installed package.
estimation_dir <- file.path(tempdir(), "estimation")
dir.create(estimation_dir, showWarnings = FALSE)

Estimation methods

method selects the estimator:

method Estimator Notes
"foce" First-order conditional estimation
"focei" FOCE with interaction The default when neither the call nor the model file sets a method
"laplace" Laplace approximation with the exact Hessian Reports a different OFV than "focei". With n_agq > 1 it becomes adaptive Gauss-Hermite quadrature
"gn", "gn_hybrid" Gauss-Newton; the hybrid finishes with a FOCEI polish step
"saem" Stochastic approximation EM Stochastic: set seed for reproducibility
"imp" Importance-sampling Monte Carlo EM With imp_eval_only = TRUE it only evaluates −2 log L and must be the last chain stage
"impmap" Importance sampling assisted by the mode a posteriori Requires mu-referencing; no IOV yet
"bayes" Full MCMC Posterior summaries in fit$bayes instead of a covariance step
vi (model file only) Variational inference Set in [fit_options]; not accepted by the method argument (see below)

The ferx-core estimation methods pages describe each algorithm. The same warfarin model fitted with each method:

The estimates are close, but OFVs are not comparable across methods. Each method computes the objective function under its own approximation. Compare OFVs only between fits made with the same method, as in Model development and selection.

Minimal runnable call

Pass method to override the model file. A character vector runs a chain: each stage starts from the previous stage’s estimates, and only the last stage produces the covariance step and diagnostics.

fit_chain <- ferx_fit(base$model, base$data, method = c("saem", "focei"), verbose = FALSE)
#> Warning: Model file [fit_options] sets `method = focei` but ferx_fit() argument
#> overrides it with `saem, focei`. The call-time value will be used.
fit_chain$method_chain
#> [1] "SAEM"  "FOCEI"
data.frame(converged = fit_chain$converged, ofv = fit_chain$ofv)
#>   converged       ofv
#> 1      TRUE -1185.462

The gradient at the reported estimates

The run log’s convergence checks read fit$final_gradient, the gradient of the objective at the reported parameter point, in the packed space the optimizer works in (Variability: random effects, residual error and IOV). Gradient-based optimizers report the gradient they already used. The derivative-free bobyqa has none of its own, so ferx computes a central finite-difference gradient after the fit instead, which is what lets you check a converged = TRUE where it is least supported. Beside a gradient-based fit of the same model:

fit_bobyqa <- ferx_fit(warf$model, warf$data, settings = list(optimizer = "bobyqa"), verbose = FALSE)
fit_lbfgs <- ferx_fit(warf$model, warf$data, settings = list(optimizer = "nlopt_lbfgs"), verbose = FALSE)
data.frame(optimizer = c(fit_bobyqa$optimizer_label, fit_lbfgs$optimizer_label),
           converged = c(fit_bobyqa$converged, fit_lbfgs$converged),
           ofv = c(fit_bobyqa$ofv, fit_lbfgs$ofv),
           largest_gradient = c(max(abs(fit_bobyqa$final_gradient)), max(abs(fit_lbfgs$final_gradient))))
#>     optimizer converged       ofv largest_gradient
#> 1      bobyqa      TRUE -280.3595     0.0017453665
#> 2 nlopt_lbfgs      TRUE -280.3595     0.0002354352
round(fit_bobyqa$final_gradient, 4)
#> [1] -0.0017 -0.0016 -0.0002  0.0001  0.0006 -0.0002 -0.0004

The run log’s convergence check reads the same vector. It scales each component by its parameter and compares it with gradient_tol:

bobyqa_log <- strsplit(ferx_runlog(fit_bobyqa, verbose = FALSE), "\n")[[1]]
start_gradient <- grep("Relative gradient", bobyqa_log)
cat(bobyqa_log[(start_gradient - 1):(start_gradient + 1)], sep = "\n")
#>   All 7 relative gradient components satisfy |grad * param| <= 0.1.
#>   Relative gradient (grad * |param|):
#>   [ -0.0002321  -0.01275  -0.000123  2.384e-06  5.743e-06  -6.696e-05  -4e-06 ]

Both fits report convergence at the same optimum: their OFVs differ by less than 0.001. The largest gradient component of the bobyqa fit, 0.002, is larger than the 0.0002 of nlopt_lbfgs, but neither is a yardstick on its own. bobyqa stops on the change in the objective and the size of its steps, not on the gradient (see its polish legs), and nlopt_lbfgs stops on its own tolerances. The run log’s check is the yardstick: every component of the bobyqa fit passes it at the default gradient_tol of 0.1. A component that fails it beside converged = TRUE is the sign to refit with a gradient-based optimizer and compare.

The finite-difference gradient costs one gradient’s worth of extra objective evaluations – two per free parameter – after the fit, and never feeds the optimizer, so the estimates are the same either way. report_final_gradient = FALSE turns it off when those evaluations are expensive, as in a large ODE model:

fit_no_grad <- ferx_fit(warf$model, warf$data,
                        settings = list(optimizer = "bobyqa", report_final_gradient = FALSE),
                        verbose = FALSE)
c(same_ofv = isTRUE(all.equal(fit_no_grad$ofv, fit_bobyqa$ofv)),
  gradient_is_null = is.null(fit_no_grad$final_gradient))
#>         same_ofv gradient_is_null 
#>             TRUE             TRUE

It stays NULL for the built-in BFGS and for SAEM, which report no gradient at all.

Options that matter

Arguments of ferx_fit()

Argument Default Meaning
method NULL Estimation method or chain (above)
threads NULL Worker threads for the per-subject loops; NULL uses available cores minus one, at most 8
gradient NULL Inner-loop gradient: "auto" (analytic where available) or "fd" (finite differences); NULL uses the model file
optimizer_trace FALSE Record the optimizer trace
settings NULL Named list of engine settings (tables below); a key that duplicates a dedicated argument is an error

The base model’s file requests finite differences (gradient = fd). With "auto" the analytic gradient is used and the fit takes fewer objective evaluations. Pinning threads changes speed, not results:

fit_auto <- ferx_fit(base$model, base$data, gradient = "auto", verbose = FALSE)
#> Warning: Model file [fit_options] sets `gradient = fd` but ferx_fit() argument
#> overrides it with `auto`. The call-time value will be used.
fit_1thread <- ferx_fit(base$model, base$data, threads = 1, verbose = FALSE)
data.frame(
  fit = c("model file (fd)", "gradient = auto", "threads = 1"),
  gradient_used = c(fit$gradient_used, fit_auto$gradient_used, fit_1thread$gradient_used),
  evaluations = c(fit$n_iterations, fit_auto$n_iterations, fit_1thread$n_iterations),
  threads = c(fit$n_threads_used, fit_auto$n_threads_used, fit_1thread$n_threads_used),
  ofv = c(fit$ofv, fit_auto$ofv, fit_1thread$ofv)
)
#>               fit gradient_used evaluations threads       ofv
#> 1 model file (fd)            fd         386       3 -1185.462
#> 2 gradient = auto      analytic          44       3 -1185.462
#> 3     threads = 1            fd         386       1 -1185.462

Switching the gradient moved a second factor as well. With optimizer left at auto, ferx chooses the outer optimizer to suit the gradient, so the two fits did not use the same one, and the model-file fit says so in a general warning:

c(model_file = fit$optimizer_label, gradient_auto = fit_auto$optimizer_label)
#>           model_file        gradient_auto 
#>      "auto (bobyqa)" "auto (nlopt_lbfgs)"
optimizer_note <- grep("also changed the outer optimizer", fit$warnings, value = TRUE, fixed = TRUE)
cat(strwrap(optimizer_note, 90), sep = "\n")
#> gradient = fd also changed the outer optimizer: with optimizer = auto left in place it
#> resolved to bobyqa rather than the nlopt_lbfgs this model would have used under gradient
#> = auto, because auto picks the derivative-free optimizer when there is no exact analytic
#> gradient to feed a gradient-based one. Two factors moved, not one — if you are comparing
#> an fd arm against an auto arm, pin optimizer = bobyqa in both so the difference you
#> measure is the gradient.

To measure the gradient alone, pin optimizer in both fits; settings = list(optimizer = "bobyqa") on the model-file fit removes the note. fit$gradient_method_outer records the route the outer gradient took. On the covariate model of Model development and selection the route is the exact analytic gradient:

cov <- ferx_example("two_cpt_oral_cov")
fit_cov <- ferx_fit(cov$model, cov$data, verbose = FALSE)
fit_cov$gradient_method_outer
#> [1] "analytic (Dual2)"
ferx_get_warnings(fit_cov, as_df = TRUE)[, c("severity", "category")]
#>   severity           category
#> 1  warning dw_autocorrelation

Every subject got it here, so the fit carries no fallback note.

A subject outside the analytic gradient’s scope falls back to an approximation that holds its random effects fixed, and the fit then carries a general note naming how many subjects took it. That note reports the route the gradient took, not a defect in the result; if such a fit stalls, reconverge_gradient_interval (below) re-solves the random effects every N-th evaluation.

NoteChanged after ferx-r 0.4.0

With ferx-r 0.4.0, 4 of this model’s 30 subjects take the fixed-random-effect approximation, and the fit carries that general note.

Two warnings about where a fit started

Both loops can end up reporting a number that describes their starting point rather than the model, and each has its own warning.

stalled_at_init says the outer loop never left its initial estimates: no free theta, omega or sigma moved. The OFV is then the objective of the initial values, and converged need not contradict it – a fit that never moved has a flat trace to plateau on. The honest way to see it is the case where it is expected: refit a model whose [parameters] block has been rewritten with the estimates of a converged run.

fit_warf <- ferx_fit(warf$model, warf$data, verbose = FALSE)

# Rewrite the [parameters] block with a fit's own estimates. stopifnot() stops when a
# declaration is not found, rather than writing the file back unchanged.
rewrite_inits <- function(fit, path) {
  est <- fit$estimates
  lines <- readLines(warf$model)
  for (nm in c("TVCL", "TVV", "TVKA")) {
    i <- grep(paste0("theta ", nm, "\\("), lines)
    stopifnot(length(i) == 1L)
    lines[i] <- sub(paste0("theta ", nm, "\\(([^,]+),"),
                    paste0("theta ", nm, "(", format(est[nm, "estimate"], digits = 12), ","),
                    lines[i])
  }
  for (nm in c("ETA_CL", "ETA_V", "ETA_KA")) {
    i <- grep(paste0("omega ", nm, "\\s*~"), lines)
    stopifnot(length(i) == 1L)
    lines[i] <- sub("~.*$", paste0("~ ", format(est[nm, "estimate"], digits = 12)), lines[i])
  }
  i <- grep("sigma PROP_ERR\\s*~", lines)
  stopifnot(length(i) == 1L)
  lines[i] <- sub("~.*$", paste0("~ ", format(est["PROP_ERR", "estimate"], digits = 12), " (sd)"),
                  lines[i])
  writeLines(lines, path)
  lines
}

restart <- file.path(estimation_dir, "warfarin_restart.ferx")
grep("theta |omega |sigma ", rewrite_inits(fit_warf, restart), value = TRUE)
#> [1] "  theta TVCL(0.132974307827, 0.001, 10.0)"
#> [2] "  theta TVV(7.73056793678, 0.1, 500.0)"   
#> [3] "  theta TVKA(0.725258263211, 0.01, 50.0)" 
#> [4] "  omega ETA_CL ~ 0.0285972641781"         
#> [5] "  omega ETA_V  ~ 0.00957815634583"        
#> [6] "  omega ETA_KA ~ 0.348919133884"          
#> [7] "  sigma PROP_ERR ~ 0.0107480748946 (sd)"
fit_restart <- ferx_fit(restart, warf$data, settings = list(optimizer = "bobyqa"), verbose = FALSE)
fit_restart_slsqp <- ferx_fit(restart, warf$data, settings = list(optimizer = "slsqp"), verbose = FALSE)
data.frame(optimizer = c("bobyqa", "slsqp"), ofv = c(fit_restart$ofv, fit_restart_slsqp$ofv),
           converged = c(fit_restart$converged, fit_restart_slsqp$converged),
           stalled_at_init = c(fit_restart$stalled_at_init, fit_restart_slsqp$stalled_at_init))
#>   optimizer       ofv converged stalled_at_init
#> 1    bobyqa -280.3595     FALSE            TRUE
#> 2     slsqp -280.3595      TRUE            TRUE
restart_warnings <- ferx_get_warnings(fit_restart, as_df = TRUE)
restart_warnings[, c("severity", "category")]
#>   severity           category
#> 1 critical        convergence
#> 2  warning dw_autocorrelation
#> 3  warning    stalled_at_init

Here the start really was the optimum, so stalled_at_init is expected and harmless. What converged says beside it can depend on the optimizer: here it is TRUE under slsqp and FALSE under bobyqa. A stalled fit reported as converged is the case the warning exists for, since nothing else would flag it. Either way, read stalled_at_init first. On a first fit from a model file’s own initial values the same warning says the OFV carries no information about the model, and the remedy is different starting values, a gradient-based optimizer, or a look at final_gradient. Model development and selection gates candidates on the same verdict through reject_init_stall.

The same rewrite can seed a refit from the bobyqa fit of the final-gradient comparison above, which stopped 0 OFV units short of the optimum:

from_bobyqa <- file.path(estimation_dir, "warfarin_restart_bobyqa.ferx")
invisible(rewrite_inits(fit_bobyqa, from_bobyqa))
fit_from_bobyqa <- ferx_fit(from_bobyqa, warf$data, settings = list(optimizer = "bobyqa"),
                            verbose = FALSE)
data.frame(seed = c("converged fit", "bobyqa fit"),
           seed_ofv = c(fit_warf$ofv, fit_bobyqa$ofv),
           stalled_at_init = c(fit_restart$stalled_at_init, fit_from_bobyqa$stalled_at_init))
#>            seed  seed_ofv stalled_at_init
#> 1 converged fit -280.3595            TRUE
#> 2    bobyqa fit -280.3595            TRUE

That refit stalls as well: started so close to the optimum, bobyqa finds nothing to improve. So stalled_at_init says the optimizer did not move, not that the start was the optimum. Compare the OFV with a fit that is known to have converged before reading a stall as harmless.

ebe_start_dependent is the inner loop’s version. It fires when re-solving the empirical Bayes estimates from a cold start at the final parameters scores materially worse than the estimates the optimizer minimised against – either the individual objective has more than one mode, or the inner loop cannot reach it from a cold start within inner_maxiter. The reported OFV is the better of the two EBE sets – the message names both – so the warning does not by itself put the estimates in doubt. What it limits is everything derived from the EBEs: IPRED, IWRES, CWRES, shrinkage and the covariance step (Diagnosing the model). Raise inner_maxiter to rule out the budget, and inner_restarts for a suspected second mode, then compare. The cold starts that inner_restarts adds begin with a quasi-random screen of inner_screen points, which finds a mode that lies off every single axis; inner_screen = 0 leaves only the per-axis starts.

The warning also fires in the other direction, and then it does put the estimates in doubt: when the cold re-solve scores materially lower than the objective the optimizer minimised, some subjects’ EBEs stayed in a higher mode for the whole fit, so the estimates minimise the wrong objective. ferx restarts the fit from its estimates; if the restart cannot run or leaves a gap of its own, the fit is reported with converged = FALSE (ferx-core warning codes). The message says which direction it is.

“Materially” is a small margin relative to the OFV, so on a fit that stops at a fragile point the warning can come and go with rounding. The bundled SDE fit of Experimental features, which stops at a saddle point, raises it on some machines and not on others.

A starved inner loop is a different failure. When too many subjects’ inner loops fail to converge – a larger fraction of them than max_unconverged_frac, 0.1 by default – ferx rejects the outer trial and returns a penalty instead of an objective. Cutting inner_maxiter far below its default does that on warfarin, and the fit says so:

fit_starved <- ferx_fit(warf$model, warf$data, settings = list(inner_maxiter = 1), verbose = FALSE)
starved_warnings <- ferx_get_warnings(fit_starved, as_df = TRUE)
rbind(default_budget = fit_warf$theta, inner_maxiter_1 = fit_starved$theta)
#>                      TVCL      TVV      TVKA
#> default_budget  0.1329743 7.730568 0.7252583
#> inner_maxiter_1 0.0501688 8.331656 0.3420642
data.frame(converged = fit_starved$converged, ofv = fit_starved$ofv, default_ofv = fit_warf$ofv)
#>   converged      ofv default_ofv
#> 1     FALSE 1125.951   -280.3595
starved_warnings[starved_warnings$severity == "critical", c("severity", "category")]
#>   severity         category
#> 4 critical      convergence
#> 8 critical condition_number

The fit ends 1406 OFV points above the default-budget fit, is marked unconverged and carries a critical convergence warning, so it cannot pass for a result. Leave inner_maxiter at its default unless you have a reason, and compare a reduced budget against a fit with the default before trusting it.

NoteChanged after ferx-r 0.4.0

In ferx-r 0.4.0, a fit whose every outer trial is rejected this way converges on the penalty and reports converged = TRUE at the midpoint of its declared bounds, with no convergence warning (ferx-core #1617, fixed after that release). This warfarin fit does that there. With 0.4.0, estimates sitting exactly on the midpoints of their bounds are the sign.

Choosing the outer optimizer on warfarin:

The optimizers agree to within a small tolerance on this model. A clearly higher OFV for one optimizer would point to a convergence problem with it on your model. global_search = TRUE runs a global search before the local optimizer:

fit_global <- ferx_fit(warf$model, warf$data,
                       settings = list(global_search = TRUE, global_maxeval = 500), verbose = FALSE)
data.frame(converged = fit_global$converged, ofv = fit_global$ofv)
#>   converged       ofv
#> 1      TRUE -280.3595

Multi-start

n_starts > 1 runs several fits from perturbed starting values and keeps the converged result with the lowest OFV. Start 0 always uses the model file’s exact values; the rest are perturbed by start_sigma. It is worth reaching for on the surfaces that are prone to local minima – Michaelis-Menten elimination and its VMAX/KM ridge, a full block omega over three or more etas, or many correlated covariate parameters – and the starts share the same thread pool as the per-subject loops, so the wall time grows with the number of starts rather than staying flat – the timing below shows what it costs on this machine. Widen start_sigma when the surface is ridge-shaped rather than merely bumpy. The bundled mm_multistart model (Michaelis-Menten elimination) sets n_starts = 8 in its model file:

mm <- ferx_example("mm_multistart")
ferx_model_get_section(mm$model, "fit_options")
#> # [fit_options]
#>   method           = focei
#>   maxiter          = 500
#>   covariance       = true
#>   n_starts         = 8
#>   start_sigma      = 0.5    # wider perturbation for a ridge-shaped surface
#>   multi_start_seed = 42

start <- Sys.time()
fit_single <- ferx_fit(mm$model, mm$data, settings = list(n_starts = 1), verbose = FALSE)
#> Warning: Model file [fit_options] sets `n_starts = 8` but ferx_fit() argument
#> overrides it with `1`. The call-time value will be used.

On this build the single start already reaches the same OFV, so here the extra starts only confirm it, at several times the wall time. That is the outcome you hope for rather than evidence that multi-start is unnecessary – the alternative is not knowing whether the one start you ran was the good one. When a start other than the first wins, an info note in the multi_start category says which. Here one did, but only by less than the printed precision of the OFV, so the single start has the same value to every digit shown; which start comes out lowest by such a margin can differ from one machine to the next.

The two remedies for a stuck fit overlap, and ferx says how it resolves that rather than leaving you to guess. The global pre-search ignores its starting point by design, so running it on every perturbed start would overwrite the perturbation; instead it runs on start 0 only, and the remaining starts are ordinary perturbed local fits:

fit_both <- ferx_fit(warf$model, warf$data, verbose = FALSE,
                     settings = list(global_search = TRUE, global_maxeval = 200, n_starts = 2))
both_notes <- ferx_get_warnings(fit_both, as_df = TRUE)
both_notes[both_notes$category == "optimizer_config", "message"]
#> [1] "global_search = true with n_starts = 2: CRS2-LM only runs on start 0 (it ignores the starting point and would override the theta perturbation on starts 1..2)"

So the two do combine, with the division of labour the note describes: the global search looks for the basin from the file’s own values, and the perturbed starts probe around it. The note is info, not a refusal.

How those proposals are tuned is set by three defaults. scale_adaptation = "robbins_monro" adjusts each subject’s step scale every iteration towards the target acceptance rate, but leaves it alone while the acceptance rate is inside scale_deadband. n_mh_steps = "auto" sizes the number of proposals from the data. mstep_damping is off except in models with iiv_on_ruv. interval is the older rule, which rescales only every adapt_interval iterations. Thetas that no random effect reaches

SAEM moves most thetas through their random effects: a typical value such as TVCL follows the mean of its eta, and a covariate exponent is updated together with the typical value it scales. A theta that no such update reaches is left to a numerical M-step instead, which ferx-core describes as noisier and able to settle away from the optimum (thetas the closed-form update cannot reach). Two settings act on that step: mstep_solver = "score_sa" replaces its derivative-free solver, and mstep_draws averages that solver’s objective over several E-step draws instead of one.

The covariate model of Model development and selection has an exponent that two updates want: THETA_WT scales both CL and V1. ferx updates the two typical values and their shared exponent in one joint M-step, and the fit’s note says so. A SAEM fit’s own OFV is a FOCE approximation, so the fits are compared on the importance-sampled −2 log-likelihood at their final estimates (Importance sampling, below), across the schedule and M-step settings:

# Fit, then evaluate the importance-sampled -2 log-likelihood at the final estimates.
# suppress the R warnings that report overriding the model file's method and covariance setting
is_fit <- function(model, method, settings = list()) {
  suppressWarnings(ferx_fit(model, cov$data, method = c(method, "imp"), covariance = FALSE,
                            settings = c(list(imp_eval_only = TRUE, imp_seed = 1), settings),
                            verbose = FALSE))
}
mstep_fits <- list(
  focei = is_fit(cov$model, "focei"),
  saem = is_fit(cov$model, "saem", list(seed = 1)),
  saem_300_700 = is_fit(cov$model, "saem", list(seed = 1, n_exploration = 300, n_convergence = 700)),
  saem_score_sa = is_fit(cov$model, "saem", list(seed = 1, mstep_solver = "score_sa")),
  saem_4_draws = is_fit(cov$model, "saem", list(seed = 1, mstep_draws = 4))
)
joint_note <- grep("joint M-step", mstep_fits$saem$warnings, value = TRUE, fixed = TRUE)
cat(strwrap(joint_note, 90), sep = "\n")

Running a fit in the background

In an interactive session, ferx_fit_async() starts the fit in a background process and returns a ferx_job handle immediately. It accepts the same model, data and other arguments as ferx_fit(). When R is not interactive (scripts, knitr, and so this book), it runs a normal fit and returns the result:

fit_bg <- ferx_fit_async(base$model, base$data, verbose = FALSE)
class(fit_bg)
#> [1] "ferx_fit"

The handle functions therefore only make sense interactively. They are shown here without being run:

job <- ferx_fit_async(base$model, base$data, tail_n = 6, poll_interval = 0.5)
job                          # print(): status of the background job
plot(job)                    # trace so far
job$trace_path               # path of the trace file, once written
fit <- ferx_collect(job, verbose = TRUE)   # wait, showing progress, and return the fit
ferx_stop(job)               # or: stop the job

tail_n is the number of recent trace rows shown per poll in ferx_collect(), and poll_interval is the time between polls in seconds.

#> overrides it with `saem`. The call-time value will be used.

strwrap(w_saem$message[grepl("not used by method", w_saem$message)], 80)

#> [2] "Method-specific options for `SAEM`: adapt_interval, conddist, conddist_burnin,"
#> [3] "conddist_keep_samples, conddist_nsamp, inner_maxiter, inner_optimizer,"        
#> [4] "inner_tol, mstep_damping, mstep_draws, mstep_solver, n_convergence,"           
#> [5] "n_exploration, n_leapfrog, n_mh_steps, omega_burnin, saem_conddist,"

  • Convergence of stochastic methods. SAEM, IMP, IMPMAP and Bayes depend on the random seed and on their iteration or sample counts. Check fit$bayes$rhat and the effective sample sizes, and the ESS in fit$importance_sampling, before using the results.

  • Do not compare OFVs across methods. Refit competing models with the same method.

Warnings you may see here

See the ferx-core warnings page for the full descriptions.

  • optimizer_health (warning): the trust region collapsed or the optimizer degenerated. Try a different optimizer or rescale parameters.

  • stalled_at_init (warning): no free parameter left its initial estimate, so the OFV describes the starting values rather than the model. It can arrive alongside converged = TRUE, which is why it is a warning of its own rather than a convergence warning; whether converged agrees depends on the optimizer (above).

  • ebe_start_dependent (warning): the empirical Bayes estimates, and every diagnostic built on them, depend on where the inner loop starts. Raise inner_maxiter, or inner_restarts for a suspected second mode (above).

  • gradient_fallback (info): a slower fallback gradient or sampler path was taken.

  • mu_referencing (warning or info): mu-referencing is missing or partial. Prefer forms like CL = TVCL * exp(ETA_CL) for SAEM and Bayes.

  • optimizer_config (warning or info): a note on, or failure of, the global_search configuration.

  • multi_start (info): which start of a multi-start fit won, when it was not the first.

  • cancelled (info): the run was cancelled by the user.

  • threads (info): a note on thread-count efficiency.

  • flat_parameter (warning): a theta has no effect on the objective at its initial value and was frozen there. Map it into the model or remove it.

  • init_outside_bounds (warning): an initial estimate lay outside an internal limit and was clamped before the first evaluation.

  • init_not_representable (warning): an initial estimate that the optimizer cannot represent at all, such as a positive theta started at or below the floor of the log scale it is estimated on (the message gives the value). The value is moved before the first evaluation, so the fit does not start where the file says. Here a TVKA started at 1e-12, inside its own bounds:

    tiny_start <- file.path(estimation_dir, "warfarin_tiny_ka.ferx")
writeLines(sub("theta TVKA(1.0, 0.01, 50.0)", "theta TVKA(1e-12, 0.0, 50.0)",
               readLines(warf$model), fixed = TRUE), tiny_start)
fit_tiny <- ferx_fit(tiny_start, warf$data, verbose = FALSE)
tiny_warnings <- ferx_get_warnings(fit_tiny, as_df = TRUE)
cat(head(strwrap(tiny_warnings$message[tiny_warnings$category == "init_not_representable"], 90), 3),
    sep = "\n")
#> W_INIT_NOT_REPRESENTABLE: TVKA is declared as 1e-12 but the optimizer sees 1.000000e-10 —
#> ferx packs it on the log scale, and `ln` has no value at or below 0, so the packer
#> substitutes a floor of 1e-10, which the optimizer's own box then clamps to 1.000000e-10.

    Here the fit does not recover. It reports convergence, but at OFV -265.33 against -280.36 from the model file’s start, with TVV at 0.19 instead of 7.73: the substituted start sent the optimizer to another basin. Declare the start at a value the parameter can take, and do not read converged as a sign that the start did no harm.

    NoteChanged after ferx-r 0.4.0

    With ferx-r 0.4.0, the fit from this start also ends far from the optimum, and carries critical warnings besides.

  • parameter_at_runaway_guard (warning or critical): a parameter is pinned at a hidden optimizer guard. collapse (warning) means remove or simplify it; runaway (critical) means reject the fit.

  • importance_sampling (warning): the effective sample size dropped to zero, or the proposal collapsed. Increase the samples or improve the proposal.

  • vi_bad_basin (critical): the final bound-quality check of a VI fit failed, and the fit is marked unconverged. Try new starting values, or start from another method.

Summary

  • Choose the estimator with method, chain methods with a vector, and compare OFVs only within one method.
  • Follow the optimizer with optimizer_trace = TRUE, ferx_trace(), plot(fit) and ferx_runlog().
  • Tune the fit through settings. The generated tables above list every setting that controls estimation, and ?ferx_fit documents them all.
